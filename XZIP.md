# xzip changes to PLzmaSDK

Branch `tmp/xzip-codecs`, based on upstream tag `1.6.1` (`f449bc3`). Everything here exists for the xzip app
(blabla-yy/unarchive-swiftui) and is kept as a small, separable set of additions so it can be rebased onto
a newer upstream.

| Change | Where |
|---|---|
| BZip2 decoder (7z method 040202), on the system libbz2 | `src/CPP/7zip/Compress/BZip2Decoder.*`, `BZip2Register.cpp` |
| Deflate decoder (040108), on the system zlib | `src/CPP/7zip/Compress/DeflateDecoder.*`, `DeflateRegister.cpp` |
| Deflate64 decoder (040109), on zlib's `contrib/infback9` (vendored, unmodified) | same files, `src/C/infback9/` |
| Shared decode loop for the two pull-style libraries | `src/CPP/7zip/Compress/PullDecoderLoop.h` |
| An item failure's reason names 7-Zip's operation result (`unsupportedMethod:<methods>`, `dataError`, `crcError`, `unexpectedEnd`, `dataAfterEnd`, `unknown`); the `what` is unchanged | `src/plzma_extract_callback.cpp` (`setOperationResultReason`) |
| A 7z item stored without a name is listed and extracted as `[Content]` (or `[Content] <n>` when the archive has several items) instead of failing with "Can't read item path." — unless 7-Zip flagged the headers as broken, where the name was unreadable rather than absent | `src/plzma_item_name.hpp`, used by the open and extract callbacks |
| Extraction hands 7-Zip every index in one `Extract` call instead of 256 at a time; for a solid archive each call decoded the block from its start, so time grew with the square of the entry count (COMPRESS-592, 70001 entries: 5 s → 0.06 s) | `src/plzma_extract_callback.cpp` (`ExtractCallback::process`) |
| Registrators 18–20 for the three codecs; libbz2 and libz linked | `src/plzma_private.h`, `src/plzma.cpp`, `Package.swift` |
| A tar header whose mtime field starts with NUL (AIX writes a symlink's as NUL + digits) reads as time 0, as 7-Zip 26.03 and bsdtar do, instead of being refused — which ended the listing at that entry | `src/CPP/7zip/Archive/Tar/TarIn.cpp` (`ParseInt64_MTime`) |
| A failed open or mkdir during extraction puts the OS error into the exception's reason as a leading `errno:<n> ` token, so a caller can tell ENAMETOOLONG / ENOSPC from a permission problem. For EACCES / EPERM / EROFS / ENOENT / unknown the original sentence ("You don't have write permission or parent directory doesn't exist.") follows the token; any other errno is followed by `strerror` instead | `src/plzma_file_utils.*` (`setErrnoReason`), `src/plzma_out_streams.cpp`, `src/plzma_extract_callback.cpp` |
| An archive symlink (`kpidSymLink`, which the tar handler reports) is created as a symlink instead of a regular file holding the target text — only if it can never lead out of the extraction directory: relative target, `..` only as a leading run, and no higher than the link's own depth (checked against `realpath` of its parent). Anything else keeps the old behaviour (a regular file with the target text), so a later entry cannot be written *through* a link to somewhere outside. POSIX only | `src/plzma_symlink.hpp`, used by `src/plzma_extract_callback.cpp` |

Decoders only: nothing here can write BZip2, Deflate or Deflate64. Only `Package.swift` is updated; the
CMake, CocoaPods and Node builds are not.

Tests: `swift_pm_tests/plzmaTests/XzipTarTests.swift` (tar headers, errno reason, symlinks; tars are built in
memory), and `swift_pm_tests/plzmaTests/XzipCodecTests.swift`, fixtures in `swift_pm_tests/plzmaTests/Fixtures/xzip/`,
regenerated by `make7z.py` there (needs 7-Zip's `7zz` for the encrypted and Deflate64 ones). Run with
`swift test --enable-code-coverage`.
